## Часть 1. Бизнес-план (текст из Figma, без изменений по смыслу)

Сделай готовое приложение для записи в автосервис или детейлинг-студию. Оно должно
работать по обычной ссылке на телефоне и компьютере. Клиенту не нужно регистрироваться
или что-либо устанавливать. При желании он сможет добавить приложение на главный экран
телефона, после чего оно будет открываться без адресной строки, со своей иконкой.

Это приложение нужно для эксперимента: за сутки собираются варианты для 10–15 реальных
студий, и каждому владельцу отправляется готовая ссылка. Поэтому новое название, цены,
адрес, телефон, график и фотографии должны подставляться за несколько минут. Данные не
разбрасываются по коду: настройки каждой студии хранятся в одном файле, а владелец может
менять основные данные в своём кабинете.

**Технологии:** TypeScript, React, Vite, React Router; Astryx Design System и Phosphor
Icons; TanStack Query; Zod для пользовательского ввода; Supabase (БД, вход владельца,
фото, серверные функции); date-fns и date-fns-tz; OpenAI SDK для помощника с моделью из
настроек сервера; vite-plugin-pwa и Workbox; liquid-gl для стеклянного эффекта; Vitest и
Playwright; Vercel для публикации; pnpm.

**Вид:** тёмный интерфейс — чёрный фон, белый текст, яркий синий `#4690FF`. На главной:
большое фото машины, название студии, краткое описание, услуги с ценами, фото работ,
адрес, время работы, понятные кнопки записи. Над карточкой записи — заголовок «Запись в
студию». Внизу — стеклянная навигация «Главная», «Услуги», «Моя запись», не закрывающая
содержимое. Плавное появление разделов при прокрутке с уважением к отключённым анимациям.
На главном фото — широкая стеклянная кнопка «Записаться», которая движется вместе с
фото; при прокрутке в ней не появляются буквы соседних разделов, надпись остаётся чёткой.

**Клиент:** смотрит услуги, цены, примеры работ; выбирает услугу, дату и свободное время,
вводит имя, телефон и автомобиль, подтверждает. Занятое время явно отмечено. После
подтверждения видит подробности и может отменить по правилам студии. Свободное время —
по графику, занятости боксов, длительности услуги и времени на подготовку; двухдневная
услуга занимает бокс оба дня. Помощник на обычном языке («Когда ближайшее окно?»,
«Сколько стоит полировка?», «Как найти студию?») с примерами-кнопками; отвечает по данным
этой студии, при нехватке данных задаёт уточняющий вопрос. После записи — напоминание за
сутки, а где уведомления недоступны — добавление в календарь.

**Владелец:** отдельный кабинет со входом по почте и паролю. Записи на день и неделю,
количество заездов, завершённых работ и реально полученные деньги. Ручная запись,
перенос, отмена, отметка «принята»/«готова», оплата и возврат. Редактирование услуг, цен,
длительностей, боксов, часов работы, выходных, адреса, телефона, логотипа, главного фото
и трёх информационных карточек. Фото работ: добавить карточку, заменить конкретное фото,
изменить подпись конкретного фото; загрузка одного фото не трогает остальные. Помощник
владельца: «Что у меня завтра?», «Сколько машин было на неделе?», «Сколько денег
получено?» — по базе записей и оплат этой студии.

**Надёжность:** у каждой студии свои данные; права проверяются на сервере; ключи базы и
модели не попадают в код сайта. Запись создаётся одной неделимой операцией; из двух
одновременных записей на один бокс и время успешна только одна; повторное нажатие не
создаёт копию. Помощник сначала получает сведения через серверные функции и только потом
отвечает; не придумывает записи и окна; клиентский помощник не видит список клиентов,
помощник владельца не меняет данные по своей инициативе. Ограничены частота обращений и
расходы на модель.

**Быстрая настройка:** папка `tenants/<название>/` с одним файлом настроек и фото;
команды создания, проверки настроек, публикации и проверки готовой ссылки. До проверки
студия доступна только как образец. У каждой студии свой адрес `/s/<название>/`, иконка и
настройки установки на телефон.

**Инструменты агента:** MCP Supabase/Vercel при наличии, иначе официальные CLI; проверка на
телефоне и компьютере через браузерный MCP или Playwright; skill ui-ux-pro-max; изучение
Astryx через `build`, `template`, `component`, `docs layout`, `docs tokens`; imagegen для
временных изображений образца при наличии.

**Готово, когда:** клиент может записаться, владелец видит запись в кабинете, занятое время
нельзя забронировать повторно, помощник отвечает по настоящим данным, приложение
устанавливается на телефон, а новую студию можно подготовить без изменения исходного кода.

## Часть 2. Технические этапы

Каждый этап завершается проверкой; фактические результаты — в [ACCEPTANCE.md](ACCEPTANCE.md).

### Этап 1. Фундамент
- pnpm, Vite 8, React 19, TypeScript strict, React Router, TanStack Query, Zod.
- Astryx: `astryx init --all`, чтение AGENTS.md и документации установленной версии,
  тема через `defineTheme` + `<Theme mode="dark">`, поставляемые `reset.css`/`astryx.css`.
- shadcn Drawer одной ветки (Base UI), токены shadcn → токены Astryx, явный порядок
  CSS-слоёв с Tailwind v4 (мост Astryx).
- Локальный Supabase (CLI) для интеграционных проверок.
- **Проверка:** typecheck, oxlint, build, `astryx doctor`, Playwright foundation-смоук
  (отступы компонентов, токен Drawer, эффективный порядок слоёв).

### Этап 2. База данных
- Таблицы с `tenant_id`, составные FK `(tenant_id, id)`, RLS, строгие GRANT.
- `resource_occupancies` с `EXCLUDE USING gist` для броней и блокировок.
- Расчёт слотов в SQL (часы приёма, исключения, timezone, многодневная занятость, буфер).
- Атомарные RPC: создание, перенос, отмена, блокировка; идемпотентность; токен доступа
  (в БД только hash, повторная выдача при retry); платежи и возвраты; статистика в SQL;
  счётчики rate limit и бюджета LLM; outbox уведомлений.
- **Проверка:** SQL/integration-тесты на реальном Postgres.

### Этап 3. Конвейер студий
- `tenants/<slug>/business.json` + изображения, Zod-схема.
- `tenant:new`, `tenant:validate`, `tenant:publish`, `tenant:verify`; seed из демо-студий.
- Генерация оболочек: HTML-метаданные, manifest (id/start_url/scope), иконки, maskable,
  apple-touch-icon, startup images, отдельный service worker на scope студии.
- **Проверка:** тесты конвейера, публикация в локальный Supabase, verify по URL.

### Этап 4. Клиентское приложение
- Главная, услуги, последовательная bottom sheet записи, подтверждение, «Моя запись»,
  отмена, ICS. Состояния loading/error/empty/success. Safe area, клавиатура, Back, фокус,
  reduced motion. liquid-gl для стеклянных поверхностей.

### Этап 5. Кабинет владельца
- Вход через Supabase Auth (без публичной регистрации), членство проверяется на сервере.
- День/неделя, статистика, ручная запись, перенос, отмена, статусы, оплата/возврат,
  блокировки, настройки студии, услуги, боксы, часы, исключения, фото, карточки.

### Этап 6. AI-помощник
- Edge Function с LLM_BASE_URL/LLM_API_KEY/LLM_MODEL (OpenAI SDK), роутер намерений,
  обязательный серверный инструмент до ответа, ограниченный tool loop, JSON-intent
  fallback, разделение client/owner, бюджет и rate limit в БД.

### Этап 7. Уведомления и PWA
- Web Push (VAPID), outbox `notification_jobs` с lease и дедупликацией, Supabase Cron,
  обработка переноса и отмены; ICS с честным состоянием; injectManifest SW.

### Этап 8. Приёмка
- Playwright: услуга → подтверждение → запись видна владельцу; изоляция второй студии;
  документация: SETUP.md, CLONE-IN-6-MINUTES.md, ACCEPTANCE.md, .env.example.

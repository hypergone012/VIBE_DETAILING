# Решения и отступления

Короткий журнал решений, принятых по ходу реализации, особенно там, где актуальные
версии инструментов или окружение потребовали отойти от буквы плана.

## Источники и окружение

- **План из Figma.** Доска Figma из промпта недоступна из среды разработки; план вставлен
  в чат и сохранён в `IMPLEMENTATION-PLAN.md` (часть 1 — без изменений по смыслу).
- **Логотип SGX** в макете не использовался — по указанию автора.
- **Хостинг.** Промпт требует готовность к Cloudflare Pages, план называет Vercel. Сделано
  оба варианта из одной сборки: `vercel.json` и генерируемые `dist/_redirects` + `dist/_headers`.
  Деплой в этой сессии не выполнялся (нет аккаунтов) — см. ACCEPTANCE.md.

## Дизайн-система

- **Astryx 0.6.6** подключён через `astryx init --all --agent all`; рабочий процесс
  «шаблон → блоки → компоненты» оформлен как проектный скилл `.claude/skills/astryx`
  (в репозитории Astryx нет готового SKILL.md — он собран из сгенерированных agent docs
  установленной версии). MCP-сервер Astryx прописан в `.mcp.json`; из этой среды он
  недоступен (сетевая политика), CLI отдаёт те же документы офлайн.
- **ui-ux-pro-max** установлен из `nextlevelbuilder/ui-ux-pro-max-skill` (MIT, без тестов).
  Его сгенерированная светлая палитра и «сырые» CSS-сниппеты не приняты: палитру фиксирует
  план (чёрный, белый, один акцент студии), стили — тема Astryx. Итог — `design-system/studio-booking/MASTER.md`.
- **Тема на рантайме** (`defineTheme` на студию), без пакета `@astryxdesign/theme-*`:
  акцент приходит из базы, поэтому `astryx doctor` даёт одно предупреждение «no theme package».
- **Акцент «как есть».** Тёмный режим Astryx осветляет accent; бренд-цвет студии задан
  явными токенами, цвет текста на акценте выбирается по контрасту WCAG (`onAccentColor`).
- **Шрифт Inter Variable** — локально (`@fontsource-variable/inter`, только latin,
  latin-ext, cyrillic): работает офлайн и не требует расширять CSP.
- **shadcn Drawer — ветка Base UI** (`@base-ui/react/drawer`), без Vaul. Реестр
  ui.shadcn.com из среды недоступен; компонент взят из репозитория shadcn-ui (стиль base-nova).
  `VirtualKeyboardProvider` — внутри Root (иначе Base UI error #27).
- **Слои CSS:** `reset, theme, base, astryx-base, astryx-theme, components, utilities, app`;
  Tailwind-утилиты генерируются только для `src/components/ui`.
- **Строки списков Astryx** (`ListItem` c href/onClick) кликабельны только по подписи;
  на телефоне нажимают по всей строке — добавлен stretched-link в `@layer app`.
- **Spacing-токены Astryx заканчиваются на `--spacing-12`**; большие отступы — через `calc`.

## Стекло (liquid-gl)

- liquid-gl ставит canvas на уровень body и делает цель `pointer-events: none` с
  копированием содержимого в линзу. Поэтому линза — декоративный `GlassPane` (`content: false`),
  подпись кнопки — над ним (чёткая), а hero-кнопка снимает только `.hero__media`
  (буквы соседних секций в линзу не попадают). Для читаемости на тёмном фото над линзой
  отдельный слой подсветки края (стили самой цели liquid-gl перезаписывает).
- CSP: `worker-src 'self' blob:` нужен liquid-gl.
- Все фото студии грузятся с `crossOrigin="anonymous"`, а SW кэширует только ответы 200:
  непрозрачные (opaque) записи ломали снимки линзы.

## База и API

- **Конверт ошибок** публичных RPC `{ok:false,error,message}` вместо исключений — чтобы
  счётчики лимитов фиксировались; RPC кабинета бросают `PTxxx` (всё откатывается).
- **service_role без прав на таблицы** — только на свои RPC.
- **Токен записи** = HMAC(booking_id:idempotency_key); в базе только sha256. Повтор того же
  запроса возвращает тот же токен; `owner_issue_booking_link` выпускает новый (старый перестаёт работать).
- **`private.fail` — STABLE** (IMMUTABLE давал свёртку констант в plpgsql_check).
- **Auth:** `[auth] enable_signup = false`, но `[auth.email] enable_signup = true` — иначе
  GoTrue отключает вход по почте целиком; публичная регистрация при этом закрыта (проверено тестом).
- Вставки в `auth.users` из тестов — с `''` в токен-колонках, иначе GoTrue `listUsers` падает.

## Помощник

- Логика в `supabase/functions/_shared/assistant` на Fetch API — один код для Deno и Node
  (тесты). Edge Function зависит только от `npm:openai@7.23.0`.
- Ключи `sb_publishable_`/`sb_secret_` — не JWT: в PostgREST они идут только в `apikey`;
  `Authorization: Bearer` — только для JWT владельца. Поэтому `verify_jwt = false`, а режим
  владельца проверяется вызовом `owner_session` с его JWT.
- Период и часовой пояс: помощник и экран «Деньги» используют одни ключи периодов
  (`private.resolve_period`). Проверено: одинаковая сумма за неделю в UI и в ответе.

## Уведомления

- Web Push реализован на WebCrypto (RFC 8291 aes128gcm + RFC 8292 VAPID) вместо `web-push`
  (тот завязан на Node-модули). Корректность подтверждена эталонной `http_ece` (расшифровка).
- SSRF: подписка принимается только для хостов push-сервисов браузеров; http-эндпоинты на
  127.0.0.1/host.docker.internal — только при `push.allow_insecure_test_endpoints = true` (тесты).

## PWA

- Один `sw.js` копируется в `/s/{slug}/sw.js`: precache-URL сделаны абсолютными
  (`modifyURLPrefix`), иначе они разрешались в `/s/{slug}/assets/…` и офлайн не работал.
- Данные студии с устройства — `initialData` (устаревшие), а не `placeholderData`:
  при паузе запроса офлайн страница рендерится сразу, с плашкой «Нет подключения».
- Иконка/manifest студии строятся из `business.json` при сборке; логотип, загруженный
  владельцем в кабинете, меняет страницу сразу, а иконку приложения — после обновления
  `images/logo.png` и деплоя.

## Особенности среды разработки (не проекта)

- Edge Runtime в Docker не доверяет TLS-прокси песочницы и не может скачать `npm:openai`.
  Для локальной проверки в Deno кэш npm в томе рантайма заполнен пакетом, скачанным на
  хосте (и пустыми описаниями опциональных peer-зависимостей). В обычной среде и в облаке
  Supabase ничего такого не нужно.
- Chromium в песочнице не может подписаться на push (Google push-сервис закрыт политикой
  сети) — состояние «ошибка» в интерфейсе честное; доставка проверена через фейковый
  push-сервис и Supabase Cron.
